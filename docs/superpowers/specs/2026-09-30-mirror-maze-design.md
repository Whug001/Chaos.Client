# Haunted Theatre and Mirror Maze — Design

**Date:** 2026-09-30
**Repos:** Chaos-Server, Chaos.Client, Unora
**Status:** approved in brainstorming; this spec covers sub-project 1 (the mirror maze) in full and records the decisions for sub-projects 2 and 3.

## 1. Summary

For Halloween the Suomi theatre becomes a haunted version of itself, with decorations, harmless ghosts and
mini-games. Behind a tall mirror in the theatre lies a large mirror maze. The maze shows off client-drawn
reflections in four styles and three mirror tricks.

The work splits into three sub-projects. Each gets its own implementation plan. They ship in this order, which
the user chose:

1. **Mirror maze** — this spec, in full.
2. **Haunted theatre** — the new theatre map, the October swap, decorations, wandering ghosts.
3. **Theatre games** — bobbing for apples, the haunted mirror disguise, séance candles, and more ways to earn candy.

The Halloween window opens 2026-10-04 and closes 2026-11-04. The maze is not expected to be ready on 10-04; it
opens part-way through the window.

## 2. Decisions made in brainstorming

| Haunted theatre size | **Same shape as today** (20x31, layout 346), redecorated. |
| Monsters | **Harmless ambience only**: drifting ghosts that cannot be fought and never attack. |

| Mirror maze | Yes. A **new map behind a mirror** in the theatre. **Big** (about 60x60). |

## 3. Approaches considered for reflections

1. **Chosen — client draws reflections from a server-sent mirror list.** Each maze map has a `mirrors.json` in
   Unora. The server sends it on map entry. The client draws every character it already knows about, flipped
   across each nearby mirror and clipped to the glass. Movement is as smooth as normal walking. The server adds
   one event message, for "your double steps out", so that all nearby players see the same double.
2. **Rejected — style set by the mirror's wall art alone.** No list is needed, but window pairs and dark
   stretches need data that tile numbers cannot carry.
3. **Rejected — server-moved fake reflection creatures.** No client work, but reflections would move in
   server steps, stand on floor tiles instead of inside the glass, and could not stretch or repeat.

## 4. Sub-project 1: the mirror maze

### 4.1 The map

- New instance `suomi_mirror_maze`, about 60x60 tiles, laid out as plan B:
  - a **glass lobby** at the top, where players arrive;
  - a **funhouse wing** on the left and an **endless wing** on the right, both opening off the lobby;
  - a **haunted wing** along the bottom, joined to both side wings;
  - the **heart** in the middle, reached from the lobby through a locked door.
- Corridors are 2 tiles wide with 1-tile walls, so that most corridors pass along north- and west-facing walls.
- **Mirror placement limit.** The camera only shows walls on the north and west sides of a tile (the
  upper-right and upper-left edges on screen). Mirrors can only go on those walls.
- The first layout is generated by a script, `Unora/Tools/MirrorMaze/generate_maze.py`, using real floor and wall
  tile numbers. It writes `lod<new id>.map` and a starting `mirrors.json`. The user then tweaks the map in the
  ChaosAssetManager map editor. The script stays in the repo so the layout can be generated again.
- The map gets the next free map number after `lod10230`, chosen when the file is written.
- `instance.json` has the `eventtiming` script key, and `EventPeriod` lists `suomi_mirror_maze` under
  `EventType.Halloween`. Outside the window, players who enter are sent to the temple, as at Macabre Yard.
- If the Halloween map effects (bats, ghosts, harvest moon; another session's work, client branch
  `feat/halloween-effects`) are merged first, the maze sets their flags. The maze does not depend on them.

### 4.2 Entrance and exit

- A **tall mirror prop** stands on a theatre wall. Clicking it opens a dialog: "Step through the glass?" Yes
  warps the player to the lobby.
- The prop works in whichever theatre is open. In sub-project 1 it goes in `suomi_theatre`. Sub-project 2 moves
  it to the haunted theatre.
- Outside the Halloween window the prop says the glass is only cloudy, and does not warp.
- The lobby has a matching mirror that leads back to the theatre's mirror.

### 4.3 Mirror art

- New art: one mirror frame for each visible wall side (north and west). Each frame sits on the existing maze
  wall art. The glass is a flat dark area. The client fills it with reflections.
- The glass rectangle for each side (pixel offsets within the tile) is a constant in the client, measured from
  the final art.
- The art ships in a launcher patch, in a release folder on the Desktop.

### 4.4 `mirrors.json`

One file per maze map, beside `reactors.json`. Example:

```json
{
  "segments": [
    { "id": "lobby-n-1", "x": 12, "y": 3, "side": "north", "length": 4, "style": "glass" },
    { "id": "fun-w-2",   "x": 4,  "y": 20, "side": "west", "length": 3, "style": "funhouse", "funhouse": "tall" },
    { "id": "win-a",     "x": 30, "y": 8, "side": "north", "length": 3, "style": "window", "partner": "win-b" },
    { "id": "win-b",     "x": 30, "y": 12, "side": "north", "length": 3, "style": "window", "partner": "win-a" }
  ],
  "darkStretches": [
    { "x": 22, "y": 48, "width": 12, "height": 2 }
  ]
}
```

- `side` is `north` (the wall runs along x, on the tile's north edge) or `west` (the wall runs along y, on the
  tile's west edge).
- `style` is one of `glass`, `funhouse`, `haunted`, `endless`, `window`.
- `funhouse` is required for funhouse segments: `tall`, `wide` or `wave`.
- `partner` is required for window segments. Partners must name each other, have the same `side` and `length`,
  and lie no more than 10 tiles apart.
- The server validates the file when the map loads. It logs each invalid segment or stretch and skips it. One bad
  entry never stops the map from loading.

### 4.5 What every mirror does

- It reflects **players and creatures**, including the wandering ghosts. It does not reflect ground items,
  spell animations, names, health bars or chat bubbles.
- A character is reflected when standing within 4 tiles in front of the mirror and level with it, with one tile
  of margin at each end.
- The reflection is placed where a real mirror would put it. For a north wall at tile row `w`, a character at
  `(x, y)` reflects to `(x, 2w - 1 - y)` and facing Up and Down swap. For a west wall at column `w`, the reflection
  is `(2w - 1 - x, y)` and facing Left and Right swap.
- Only the part of the reflection inside the glass rectangle is drawn.
- Reflections are drawn as part of their wall tile, so anything in front of the wall covers them.
- A disguised player is reflected as the disguise. A hidden player is not reflected.

### 4.6 The four styles

| Style | Look |
|---|---|
| **Glass** | 60% opacity, cool blue tint (`rgba(150,180,255,0.28)` over the sprite), a slow glint that crosses the glass every ~9 s. |
| **Funhouse** | `tall`: 0.75x width, 1.5x height. `wide`: 1.35x width, 0.7x height. `wave`: normal size. All three ripple: each 2-pixel row shifts sideways by `sin(t*5 + row*0.18) * 3` px. Pink tint on tall, green on wide, alternating on wave. No glint. |
| **Haunted** | Honest most of the time, teal tint. Each haunted segment slips for 3 s at a time, at gaps of 8–20 s. The slip is one of **lag** (shows where the character was 1.1 s ago), **stare** (freezes facing out of the glass, idle frame) or **ghost** (pale green, opacity pulsing slowly between 0.2 and 0.5 at about 1 Hz). |
| **Endless** | Four copies. Copy `k` (0–3) sits `0.9k` tiles further behind the glass, scaled by `0.86^k`, with opacity `0.6 * 0.62^k`. Odd copies face the opposite way. |

**Haunted slip schedule.** The slip timing and kind come from a hash of the segment `id` and the current UTC time
in whole seconds. Every client therefore shows the same slip at the same moment, give or take clock drift. The
ghost slip pulses slowly instead of flickering, so it is safe for players sensitive to flashing light. None of
the styles go in the F4 hide-flickery-effects list.

### 4.7 The three tricks

**Your double steps out** (haunted wing only)
- The map script runs a timer. Every 20–40 s it picks one player standing within 3 tiles in front of a haunted
  segment. Each player waits at least 2 minutes between turns. If nobody qualifies, nothing happens.
- The server sends `MirrorDouble(entityId, segmentId)` to every player who can see that player.
- Each client draws the double: it climbs out of the glass over 0.6 s, follows 1 tile behind the player along
  their recent path for 6 s, then fades out over 1 s. It is drawn translucent and pale.
- The double is only a picture. It cannot be clicked, does not block anyone, and does not exist on the server.
- If the player leaves view, warps or logs off, the double fades at once.

**Window mirrors**
- Each segment of a pair shows the characters standing in front of its partner, as if looking through a window.
  They are moved across, not flipped.
- Limit: the client only knows about characters within its view range. That is why partners must be at most
  10 tiles apart, for example back to back in parallel corridors.
- About three pairs, spread across the lobby and the wings.

**Dark stretch**
- One or two corridor stretches in the haunted wing.
- Everything inside a stretch is drawn 95% black. Each player has a faint glow one tile across at their feet.
- Mirrors inside the stretch are drawn again after the darkness, at full brightness, so players steer by their
  reflections.

### 4.8 Key pieces, heart and prize

- Each wing has one **key-piece prop** near its far end. Clicking it gives the player that wing's piece and starts
  a 24-hour timed event (`mirrormaze_key_funhouse`, `mirrormaze_key_endless`, `mirrormaze_key_haunted`).
  Clicking again while it is active says you already hold this piece.
- Each player collects their own pieces. Groups do not share them.
- The **heart door** is a reactor. It lets a player through only when all three key events are active and
  `mirrormaze_daily_cd` is not. Otherwise it explains what is missing.
- The **prize chest** in the heart:
  - gives a pile of candy (amount chosen in the plan, tuned so a daily run is worth about a fifth of a Macabre
    Box);
  - starts `mirrormaze_daily_cd` (24 hours) and clears the three key events;
  - the first time ever, also gives the legend mark "Saw through the Mirror Maze" and the **Mirror Walker** emblem.
- All four timed events appear in Terminus's timed-events list.
- **Candy** is a new stackable item. In this sub-project the maze is its only source. **Thulin** trades a pile of
  candy for one Macabre Box, during the Halloween window only. Sub-project 3 adds other ways to earn and spend it.

### 4.9 Speed safeguards

- Each character is drawn once per frame into an off-screen image and reused for every mirror, the same way
  `SilhouetteRenderer` does today.
- Mirror drawing is capped at 40 sprites per frame. The reflections furthest from the local player are dropped
  first.
- The client keeps 1.5 s of position history per character, only while the current map has mirrors.

### 4.11 Tests

**Server**
- `MirrorLayoutConverter` and `MirrorDoubleConverter` round trips, matching `MapEffectsPacketConverterTests`.
- `mirrors.json` validation: unknown style, missing funhouse kind, unpaired or mismatched window partner,
  partners more than 10 tiles apart, a segment off the map. Each is skipped and logged; valid ones load.
- Double timer: picks only players near haunted segments; respects the 2-minute cooldown; does nothing with no
  candidates.
- Key pieces, door and prize: the door refuses with 0–2 pieces and on cooldown; the prize gives candy, sets the
  cooldown and clears the pieces; the mark and emblem only come the first time.

**Client**
- `MirrorMath`: reflected position and facing for north and west walls; the slip schedule returns the same
  kind and timing for the same segment and time on two independent calls; endless offsets, scale and opacity;
  window translation; the double path timing (climb, follow, fade).

### 4.12 In-game check (by the user)

1. Walk past each of the four styles.
2. With a second character, watch a haunted slip and confirm both see it at the same time.
3. See a double step out, and see it on the second character's screen too.
4. See the second character through a window mirror.
5. Cross a dark stretch.
6. Collect the three pieces, open the heart, claim the prize. Check the mark, the emblem and the candy.
7. Try the heart again and confirm it refuses.
8. Trade candy with Thulin for a Macabre Box.
9. Outside the window (or with the window moved in a test build), confirm the maze sends you to the temple and
   the theatre mirror stays cloudy.

### 4.13 Deployment

Merge order: server, then client (submodule bump to the merged server), then Unora. `CLIENT_VERSION` goes up, so
the server deploys with or before the client release. The mirror art ships in a launcher patch before or with
the client.

## 5. Sub-project 2: the haunted theatre (decisions so far)

- New instance `suomi_theatre_halloween`, a copy of layout 346 (20x31) with Halloween decorations from existing
  game art plus a few new pieces.
- During the Halloween window it **replaces** `suomi_theatre`. The name `"suomi_theatre"` is hard-coded in about
  15 places (Suomi door, Terminus theatre travel, stage and backstage invites, lantern dialog, admin map list).
  They all move behind one helper that returns the theatre open right now. Players who are inside the normal
  theatre when the window opens are moved to the haunted one.
- All director tools stay. The haunted map uses the same `suomitheatremap` script. Director rights and saved
  scenes are already shared across maps.
- The backstage room is unchanged.
- Harmless wandering ghosts use merchant templates with `WanderScript` and existing ghost sprites.
- The entrance mirror from 4.2 moves here.
- Uses the Halloween map effects if they are merged.

## 6. Sub-project 3: theatre games (decisions so far)

- **Séance candles:** started only by the director from Thulin's menu. Candles on stage light up in a sequence;
  players step on them in the same order; each round adds one candle.
- **Bobbing for apples:** a barrel on stage. Most apples give candy. A cursed apple turns the player into a
  pumpkin for a minute (sprite override, as `InfectionZombieEffect` does).
- **Haunted mirror:** pay candy to wear a random monster disguise for a few minutes (same sprite override).
- Not chosen: pumpkin hunt, find the real ghost, trick-or-treat box seats, prop scavenger hunt, Lights Out,
  Possessed, haunted trivia, costume contest, witch's cauldron.
